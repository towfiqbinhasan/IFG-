# Research Lab Paper Tracker

A web app (Vercel) **and** Android app (Capacitor APK) for a research lab to log the papers each
member reads, see what the whole lab is reading, and track conference/journal deadlines with live
countdowns. Both use one codebase and one Supabase backend.

| | |
|---|---|
| Frontend | Next.js 14 (App Router) · TypeScript · Tailwind CSS · shadcn/ui (Radix) |
| Motion | Framer Motion: page transitions, hover lift, list stagger, animated counters, skeletons, modals |
| Backend | Supabase: Postgres + Auth + Row Level Security + Storage |
| Charts | Recharts, with a colour-blind-safe palette |
| Mobile | Capacitor 6 Android wrapper + installable PWA |

## Features

- **Username + password login.** Each username maps internally to `username@lab.local`. Users
  never see an email field.
- **Roles.** `admin` and `member`. Admins create accounts with a temporary password, and the
  member must change it on first login.
- **Paper log.** Bibliographic details, PDF upload, type, topics (multi-select, with inline
  creation), status, date read, how it was read, time spent, summary, contributions,
  methodology, results, limitations, notes and a 1–5 rating.
- **Personal dashboard.** Papers read, topics covered, reading streak, hours spent,
  papers-per-month chart and a topics donut.
- **Lab-wide views.** Members directory and public profiles, papers explorer (filter by member,
  topic, type, year and status), topics page, activity feed and a lab statistics dashboard.
- **Deadlines.** Conferences and journals with four dates each, a live colour-coded countdown,
  list and calendar views, "I'm planning to submit" tracking, and a notification badge for
  deadlines within 7 days.
- **Admin panel.** Users (create, reset password, deactivate, delete, change role), paper
  moderation, topics, venues, lab settings and stats.
- **Look and feel.** Dark and light mode, a mobile bottom nav and desktop sidebar, toasts,
  empty-state illustrations and a swappable splash animation.

## Quick start (local)

```bash
npm install
cp .env.example .env.local      # fill in your Supabase URL + keys
# In Supabase SQL Editor: run supabase/schema.sql
npm run dev                     # http://localhost:3000
```

Sign in as **`admin`** with the password **`ChangeMe!2024`**. You will be asked to choose a new
password right away.

## Security model

- The service-role key is only read in `src/lib/supabase/admin.ts`. That file imports
  `server-only`, so the build fails if client code ever imports it. It is used only by
  `/api/admin/*` routes (after checking that the caller is an active admin) and by
  `/api/account/change-password`.
- RLS on every table:
  - Any signed-in user can read papers, topics, venues and profiles.
  - Members can write only their own papers, paper topics, submissions and storage folders.
  - Admins can delete anyone's content.
- A trigger stops members from changing their own `role`, `is_active`,
  `must_change_password` or `username`, even through the API.
- Deactivating a user also bans them in Supabase Auth, so their sessions can't refresh.
- New auth users always start as `member`. Only the server-side admin route can promote them.
